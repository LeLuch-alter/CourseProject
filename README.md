# Kvit

**Kvit** (от «квиты» — «мы в расчёте») — настольное приложение для учёта долгов и платежей на Java + JavaFX.
Данные хранятся в Supabase (PostgreSQL). Все записи пользователь вводит сам: приложение не подключается
к банкам и другим внешним сервисам и не начисляет проценты или штрафы.

## Возможности

- **Вход и регистрация** по email и паролю; каждый пользователь видит только свои данные.
- **Обзор** — остаток к оплате, процент погашения, итоги, долги с ближайшими и просроченными сроками,
  последние платежи, быстрые действия.
- **Долги** — таблица с поиском, фильтрами (активные, просроченные, погашенные, отменённые) и сортировкой;
  панель деталей с прогрессом, сроками и историей платежей; добавление, изменение, удаление; экспорт в CSV.
- **Платежи** — все платежи с фильтром по периоду, поиском, суммой/количеством/средним за период; экспорт в CSV.
- **Отчёты** — платежи по месяцам, остаток по кредиторам, статусы долгов, прогноз даты погашения.
- **Календарь** — сроки погашения и платежи по дням месяца; подробности выбранного дня.
- **Планировщик погашения** в карточке долга — «если платить X в месяц, когда погашу?» и
  «сколько платить в месяц, чтобы успеть к сроку».
- **Предупреждение о просрочке** на обзоре с переходом сразу к просроченным долгам.
- **Настройки** — светлая, тёмная или системная тема; язык интерфейса: русский, қазақша, English.
- **Вход** — запоминается последний email (пароль — никогда), кнопка «показать пароль»,
  автоматический выход после 15 минут бездействия.
- **Горячие клавиши** — `Ctrl+1…6` разделы, `Ctrl+N` новая запись, `Ctrl+F` поиск, `F5` обновить,
  `Enter` изменить, `Delete` удалить, `Esc` закрыть диалог.

## Технологии

- Java 22, JavaFX 22
- Maven (встроенный wrapper `mvnw`, отдельно ставить не нужно)
- Supabase: PostgreSQL + Auth
- Jackson (JSON), JUnit 5 (тесты)

## Запуск

```powershell
.\mvnw.cmd javafx:run
```

Тесты:

```powershell
.\mvnw.cmd test
```

Запускать нужно командой выше, а не кнопкой ▶ над `App.java` (VS Code сам не подключит JavaFX).

## Настройка Supabase

1. Supabase Dashboard → **SQL Editor** → **New query** → вставьте `supabase/schema.sql` → **Run**.
   Повторный запуск удаляет таблицы `debts` и `payments` вместе с данными.
2. (Необязательно) Зарегистрируйтесь в приложении, подтвердите email, затем в `supabase/sample_data.sql`
   замените `student@example.com` на свой email и выполните файл — появятся примеры долгов.

## Настройка приложения

Скопируйте `config.example.properties` в `config.properties` (Dashboard → Project Settings → API Keys):

```properties
supabase.url=https://ваш-проект.supabase.co
supabase.publishableKey=sb_publishable_...
```

Вместо файла можно задать переменные окружения `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`.
Файл `config.properties` добавлен в `.gitignore`.

## Логотип

Положите квадратный PNG (например, 256×256) в `src/main/resources/kz/kvit/ui/logo.png` — он заменит
встроенную монограмму «K» во всём приложении и в иконке окна. Без файла используется монограмма.

## Структура

```
src/main/java/kz/kvit/
├── App.java          — запуск, переключение экранов, применение темы и языка
├── config/           — config.properties (Supabase) и пользовательские настройки (тема, язык)
├── i18n/             — переводы: messages.properties (EN), messages_ru, messages_kk
├── model/            — Debt, Payment и данные для экранов
├── service/          — бизнес-правила: расчёты, проверки, отчёты, экспорт CSV, вход
├── repository/       — доступ к Supabase (REST + Auth)
└── ui/               — экраны JavaFX и общие компоненты
src/main/resources/kz/kvit/ui/
├── styles.css        — дизайн-система: токены цветов (тёмная тема) и компоненты
└── theme-light.css   — светлая тема: переопределяет те же токены
supabase/
├── schema.sql        — таблицы, ограничения, триггеры, политики доступа (RLS)
└── sample_data.sql   — тестовые данные
```

Поток данных: `экран JavaFX → сервис → репозиторий → Supabase`.

## Дизайн

Стиль спокойный, как у повседневного рабочего инструмента: нейтральный графитовый фон в тёмной теме
и светло-серый в светлой, едва заметная сетка, плоские панели с тонкими границами, без свечений,
градиентного текста и неона. Единственный цветной акцент — фиолетовый, только на главных
кнопках форм (войти, сохранить). Обе темы описаны одними и теми же токенами с разными значениями.

По принципам Windows-приложений (Fluent Design) применено то, что возможно в JavaFX: шрифты Segoe UI и иконки
Segoe Fluent Icons, заголовок окна в цвет темы, верхняя командная панель, InfoBar для сообщений,
панель деталей («список + инспектор»), горячие клавиши, состояния загрузки / ошибки / пустого списка.

Анимации короткие; постоянное движение (заполнение кольца и лёгкое покачивание карточек) есть только
на экране входа. Движущиеся элементы рисуются
из кэшированного изображения, поэтому текст не дрожит. Если в Windows выключены «Эффекты анимации»
или включена высокая контрастность, анимации отключаются.

Ограничения JavaFX по сравнению с WinUI: нет Mica/Acrylic и размытия фона, вариативный шрифт
Segoe UI Variable недоступен, в CSS нет межбуквенного интервала (добавляется в коде).

## Защита данных

| Мера | Где |
|------|-----|
| Приложение не знает пароль базы данных: подключение идёт через Supabase REST API по HTTPS | `SupabaseClient` |
| В приложении только **publishable** ключ. Сам по себе он не даёт доступа к таблицам | `config.properties` |
| Приложение откажется запускаться с секретным ключом (`sb_secret_…` / `service_role`) | `AppConfig.isSecretKey` |
| Без входа у роли `anon` нет никаких прав на таблицы | `schema.sql` |
| **Row Level Security**: пользователь видит и меняет только свои долги и платежи | `schema.sql` |
| Владелец записи (`user_id`) заполняется в базе из токена (`auth.uid()`), подделать его нельзя | `schema.sql` |
| Ограничения в базе: суммы > 0, длина текста, допустимые статусы, внешний ключ платёж → долг | `schema.sql` |
| Триггеры: платежи не могут превысить долг; сумму долга нельзя уменьшить ниже оплаченной | `schema.sql` |
| Те же правила проверяются в приложении и выводятся понятными сообщениями | `DebtValidator` |
| Токены хранятся только в памяти; пароль стирается из поля после входа | `SupabaseClient`, `LoginView` |
| Автоматический выход после 15 минут бездействия | `MainView` |
| В URL запросов попадают только числовые id, пользовательский текст — в теле JSON | репозитории |

Ограничения: publishable-ключ и URL можно извлечь из приложения — поэтому защита держится на входе
пользователя и RLS, а не на секретности ключа. Отдельной защиты от подбора пароля в приложении нет
(Supabase ограничивает частоту попыток входа). Аудит безопасности не проводился.

## Бизнес-правила

1. Сумма долга и платежа больше нуля, не больше двух знаков после запятой.
2. Каждый платёж привязан к существующему долгу текущего пользователя.
3. Оплачено = сумма платежей по долгу. Остаток = сумма долга − оплачено. Проценты, штрафы и комиссии
   **не начисляются** (ставка хранится только для справки).
4. Платёж не больше остатка, не датирован будущим днём, не вносится по отменённому долгу.
5. Статус «Погашен» ставится автоматически, когда остаток равен 0, и снимается, если платёж удалили.
6. Долг просрочен, если срок раньше сегодняшней даты, остаток больше 0 и долг не отменён.
7. Отменённые долги не учитываются в итогах и отчётах по кредиторам.
8. «Требуют внимания» — активные долги с остатком, просроченные или со сроком в ближайшие 14 дней.
9. Прогноз погашения = остаток ÷ средний платёж за последние 3 месяца (с округлением вверх).
   Это оценка без учёта процентов; без платежей за 3 месяца прогноз не строится.
10. Планировщик: месяцев до погашения = остаток ÷ платёж в месяц (вверх); платёж к сроку =
    остаток ÷ число календарных месяцев до срока (не меньше 1), округлённый вверх до целого тенге.
