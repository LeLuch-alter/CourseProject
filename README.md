# Kvit

Kvit (от «квиты», то есть «мы в расчёте») — учёт долгов и платежей. Пользователь сам записывает, кому и сколько
должен, вносит платежи и видит остаток. С друзьями можно оформить расписку, которую подтверждают обе стороны.

Курсовой проект на тему «Қарыздар мен төлемдерді есепке алу жүйесін әзірлеу». Kvit не подключается к банкам
и госсервисам и не начисляет проценты или штрафы: ставка хранится только для справки.

В репозитории две версии, которые работают с одной базой Supabase:

- `web/` — сайт на React, основная версия;
- `src/` — настольное приложение на Java + JavaFX, с которого проект начинался.

## Что умеет сайт

- Вход, регистрация, восстановление пароля по ссылке на почту.
- Обзор: остаток, процент погашения, прогноз, ближайшие сроки, последние платежи.
- Долги: поиск и фильтры, карточка долга с историей платежей, планировщик и график погашения
  (долг делится на равные платежи по месяцам, оплаченные отмечаются галочкой).
- Платежи с фильтром по периоду, отчёты по месяцам и кредиторам, экспорт в CSV.
- Календарь сроков и платежей: клик выбирает день, Shift+клик выбирает период.
- Профиль с фото и QR-кодом, по которому друг добавляет тебя с телефона.
- Друзья: поиск по @имени, личный и групповой чат в реальном времени, статус «в сети», индикатор набора.
- Расписки: дать в долг или попросить у друга. Вторая сторона подтверждает, после чего долг появляется
  у обоих, а расписку можно скачать в PDF. Платёж, внесённый одной стороной, виден и другой.
- Складчина: сумма делится поровну между тобой и выбранными друзьями.
- Напоминания о сроке: уведомление при входе и каждое утро, по желанию на email.
- Тёмная и светлая тема, языки: русский, қазақша, English. Поиск по всему сайту на `Ctrl+K`.

## Стек

Сайт: React 19, TypeScript, Vite, Tailwind CSS, Framer Motion. Данные, вход, хранение фото и чат
в реальном времени работают через Supabase (PostgreSQL, Auth, Storage, Realtime).
Настольное приложение: Java 22, JavaFX 22, Maven.

## База данных

В Supabase → SQL Editor выполнить файлы по порядку:

1. `supabase/schema.sql` — долги и платежи. Повторный запуск удаляет эти таблицы вместе с данными.
2. `supabase/schema_web.sql` — профили, друзья, чат, расписки, уведомления.
3. `supabase/schema_web_2.sql` — напоминания, график погашения, складчины, групповые чаты.
   Перед ним включить расширение pg_cron: Database → Extensions.
4. `supabase/sample_web_data.sql` — по желанию, два готовых пользователя с данными.

Демо-аккаунты из шага 4 (пароль у обоих `Kvit12345`): `aisha@kvit.demo` и `daniyar@kvit.demo`.
Они друзья, у них есть долги, расписка, складчина и переписка.

## Запуск сайта локально

Нужен Node.js 20 или новее.

```powershell
cd web
npm install
copy .env.example .env
npm run dev
```

В `web/.env` указать адрес проекта и publishable-ключ (Supabase → Project Settings → API Keys):

```
VITE_SUPABASE_URL=https://ваш-проект.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

Сайт откроется на http://localhost:5173. Если PowerShell пишет, что выполнение сценариев отключено,
используйте `npm.cmd` вместо `npm` или один раз выполните `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

## Docker

```powershell
cd web
docker compose up -d --build
```

Сайт будет на http://localhost:8085. Ключи берутся из `web/.env` и вшиваются при сборке.
Образ собирается на Node 22 и раздаётся через nginx.

## Деплой на Vercel

1. vercel.com → Add New → Project → выбрать этот репозиторий.
2. Root Directory: `web`. Framework Preset определится сам (Vite).
3. Environment Variables: `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`, те же значения, что в `.env`.
4. Deploy.
5. В Supabase → Authentication → URL Configuration: Site URL — адрес сайта на Vercel,
   в Redirect URLs добавить `https://<адрес>/**`. Без этого ссылки из писем будут вести на localhost.

Встроенная почта Supabase отправляет не больше пары писем в час. Для защиты проекта проще выключить
подтверждение почты: Authentication → Providers → Email → Confirm email.

## Настольное приложение

Скопировать `config.example.properties` в `config.properties` и вписать те же URL и publishable-ключ:

```properties
supabase.url=https://ваш-проект.supabase.co
supabase.publishableKey=sb_publishable_...
```

```powershell
.\mvnw.cmd javafx:run   # запуск
.\mvnw.cmd test         # тесты
```

Запускать нужно этой командой, а не кнопкой ▶ в VS Code: иначе не подключится JavaFX.
Подробный разбор кода приложения лежит в [docs/PROJECT_GUIDE.md](docs/PROJECT_GUIDE.md).

## Безопасность

- В клиенте только publishable-ключ. Сайт и приложение откажутся запускаться с секретным ключом.
- На всех таблицах включён Row Level Security: каждый видит только свои записи, а расписку и переписку
  видят только её участники.
- Подтвердить расписку может только вторая сторона, и только через функцию в базе.
- От заёмщика нужен лишь номер карты для перевода, 16 цифр. Срок действия и CVV не запрашиваются и не хранятся.
- Платёж не может быть больше остатка: это проверяют и приложение, и триггер в базе.
- Ключи (`.env`, `config.properties`) в git не попадают.

Это учебный проект, аудит безопасности не проводился. Расписка в PDF — договорённость двух людей,
а не нотариальный документ.

## Бизнес-правила

1. Суммы больше нуля, не больше двух знаков после запятой.
2. Оплачено — сумма платежей по долгу, остаток — сумма долга минус оплачено.
3. Платёж не больше остатка, не датирован будущим днём и не вносится по отменённому долгу.
4. Когда остаток становится нулём, долг сам получает статус «Погашен».
5. Долг просрочен, если срок прошёл, остаток больше нуля и долг не отменён.
6. Отменённые долги в итоги не входят.
7. Прогноз: остаток делится на средний платёж за последние три месяца, результат округляется вверх.
